# 有无插件使用体验差异报告

> 对象：`dsh-ui-polish@0.4.0`（开发中版本）
> 环境：dsh 0.2.1-rc.5，隔离实例 `127.0.0.1:3311`，`DSH_HOME=.testenv/dsh-home`，dsh-context 0.78.0 + dsh-better-sidebar 0.28.2 共存
> 基线：**同一实例、同一会话、同一窗口尺寸**，通过「界面打磨 → 总开关」关闭/开启插件效果；不是卸载插件，因此基线仍能看到设置入口
> 方法：DOM/计算样式、动画状态、CSS 规则、音效调度计数、命中区 `elementFromPoint` 探针；未做正式用户研究，主观部分标注为设计评估

## 1. 结论摘要

插件开启后，差异集中在四个可感知层面：

1. **滚动边界更柔和**：从硬切边变为 28px、7 档非线性的羽化，Retina 下不易出现色阶断层；对话流与第三方插件面板使用同一套参数。
2. **阅读更稳**：正文使用 `text-wrap: pretty`、标题 `balance`、时间/用量/代码等宽数字；暗色正文按可变字体做轻微字重补偿。
3. **反馈更明确**：新消息短促入场；流式时输入框下方 1.8s 呼吸 + 1.1s 扫光，推理分隔点同步 1.8s 光环；可选发送/完成/出错三声合成提示音。
4. **操作与第三方界面更一致**：输入区 22–34px 小控件获得 5px/2px 的隐形命中区扩展；第三方插件的过渡节奏与滚动渐隐自动跟随，无需插件作者适配。

代价是**设置项变多**（总开关 + 8 组 + 弹簧档位），且音效默认关闭、弹簧档位需要用户主动选择；所有效果都可逐组回退。

## 2. A/B 量化指标

| 指标 | 关闭插件效果（总开关 off） | 开启插件（默认配置） |
|---|---|---|
| html 门控 | 全部 `off` | `motion/elevation/fades/glow/plugins/optics/targets` 为 `on`，`sound` 默认 `off` |
| `--ds-ease-in-out` | 宿主原生 `cubic-bezier(.33,1,.68,1)` | `cubic-bezier(0.16, 1, 0.3, 1)`（CDS easeSwift） |
| 发丝描边 token | `#ffffff0d`（暗色原生） | `#ffffff14`（约 8% 白） |
| Level-2 阴影 | 宿主原生两层静态阴影 | `inset 0 0 0 1px #ffffff0d, 0 2px 4px 0 #0000003d, 0 6px 16px 0 #0000003d` |
| 对话滚动 mask | `none` | 28px 七档渐变；顶部实际位置 `4.2 / 8.4 / 12.6 / 16.8 / 21 / 24.36 / 28px` |
| 渐隐目标数 | 0 | 2（对话 + 当前面板） |
| 第三方重定时影子表 | 0 张 | 1 张（`.12s/.15s → .144s/.18s`，v0.3.0 实测，架构未变） |
| 正文 `text-wrap` | `wrap` | `pretty` |
| 暗色正文 `font-weight` | `400` | `390`（可变字体；Windows 静态字体回退 400） |
| 时间/代码数字 | `normal` | `tabular-nums` |
| 新消息动画 | `none` | `polish-message-enter`（时长随弹簧档位，默认 0.35s） |
| 流式光晕 | `none` / 透明 | 1.8s 呼吸 + 1.1s 扫光；推理点 1.8s 光环（v0.3.0 实测，逻辑未变） |
| 弹簧档位 | 无 | 4 档：轻快 0.22s / 从容 0.35s / 弹性 0.58s / 咬合 0.32s |
| 音效 | 无 | 默认关闭；开启后 AudioContext `running`，发送提示 1 次、完成提示再 1 次（振荡器计数 1→2） |
| 输入区命中区 | 28×28 按钮，4px 上方命中父容器 | 同一位置命中按钮；命中区 32×38（伪元素 `inset:-5px -2px`） |
| 设置分区行数 | 10（插件仍在内存，总开关关闭） | 10（总开关、8 组、弹簧档位） |

> `maskStops` 的 DOM 字符串按逗号切分会把 `rgba()` 内部逗号算进去，因此报告使用实际停止点位置，而不是字符串计数。

## 3. 分维度体验差异

### 3.1 阅读与滚动

- **关闭**：滚动到边界时文字被容器硬边切断；长回答的末行可能出现孤字；数字与时间刷新时宽度跳动。
- **开启**：边缘 28px 内按 `y≈x^1.5` 的感知曲线淡出，顶部/底部各自独立；正文 `pretty` 减少末行孤字，标题 `balance` 让多行标题更均匀；时间、轮次、用量、代码使用等宽数字，流式计数不再左右抖。
- **暗色**：可变字体正文降到 390，黑底白字的“膨胀/发糊”感略减；静态系统字体自动忽略，不会强行改变字形。

### 3.2 动效与物理

- **关闭**：宿主只有单一 `--ds-ease-in-out` 与固定时长；消息直接出现；没有统一的弹簧手感。
- **开启**：基础令牌换成 `easeSwift`；新消息以弹簧曲线入场；设置开关、光晕入场共用同一档弹簧。四档手感来自二阶阻尼振子采样：
  - 轻快 600/30，过冲 8.8%，220ms；
  - 从容 320/28，过冲 1.8%，350ms（默认）；
  - 弹性 380/18，过冲 19.4%，580ms；
  - 咬合 1200/80/0.1，零过冲，320ms。
- **实测**：选择「弹性」后 `data-polish-spring=bouncy`，开关过渡 `0.58s`，曲线含 `1.1926` 峰值；选择会持久化到 localStorage。
- **注意**：这些弹簧只作用于本插件自有动效（消息入场、开关、光晕），不会覆盖宿主按钮的 `background/color` 过渡。

### 3.3 状态与音效

- **关闭**：生成过程只有原生 spinner/文字，完成时没有声音提示。
- **开启**：输入框下方细线光晕呼吸 + 扫光，推理分隔点出现同色光环；流式结束后自动复位。开启「轻量交互音效」后，发送与完成各播一声短促合成音，出错播下行音。
- **音效实现**：Oscillator + Gain 包络，无外部音频文件；默认关闭；首次启用/首次交互时解锁 AudioContext。AudioWorklet 未采用，原因见 `CDS-ASSET-MAP.md`。
- **实测**：启用后 `AudioContext.state=running`；发送后振荡器计数 1，完成后 2，说明发送/完成两声都被调度。

### 3.4 操作命中区

- **关闭**：输入区 28×28 的添加/权限/模型按钮，以及 22px 高的统计胶囊，实际可点区域就是视觉尺寸。
- **开启**：通过透明 `::after` 向上下各扩 5px、左右各扩 2px；视觉尺寸完全不变。实测在添加按钮上方 4px 处点击，开启时命中按钮，关闭时命中父容器。
- **取舍**：没有扩大到 44px，避免相邻控件命中区重叠导致误触。

### 3.5 第三方插件界面

- **关闭**：dsh-context / better-sidebar 的滚动面板没有边缘羽化，过渡时长保持各自原值。
- **开启**：泛用引擎为插件滚动容器打标，使用同一套 28px 七档 mask；影子样式表把第三方 `transition-duration` 统一放慢 1.2×（`.12s/.15s → .144s/.18s`），不改插件 CSSOM，关闭即整表移除。
- **实测**：开启时存在 1 张 `dsh-ui-polish/plugin-motion.css` 影子表，关闭后为 0；插件面板的 mask 与对话流同参数。

### 3.6 可逆性

- 总开关关闭后：门控全部 `off`、渐隐目标 0、mask `none`、影子表 0、令牌内联值撤回、正文回到 `wrap/400/normal`、消息动画 `none`。
- 重新开启后：上述指标全部恢复；实测 on → off → on 三轮一致。
- 组级开关与弹簧档位独立持久化；音效默认关闭，不会在用户不知情时发声。

## 4. 场景化差异

| 场景 | 关闭插件 | 开启插件 |
|---|---|---|
| 发送一条消息 | 消息直接出现，无入场；无声音；输入区下方无状态反馈 | 消息短促入场；可选发送音；光晕进入呼吸状态 |
| 等待长回答 | 只能看原生加载态 | 呼吸+扫光持续提示“仍在生成”；推理分隔点发光 |
| 阅读长回答并滚动 | 文字在容器边缘被硬切 | 28px 羽化提示还有内容；数字/标点观感更稳 |
| 回到旧轮次 | 无可感知边界提示 | 顶部/底部按可滚方向独立淡出 |
| 点击输入区小图标 | 需要较精准地点中 22–34px 控件 | 隐形命中区扩大，视觉不变 |
| 打开 dsh-context 面板 | 无渐隐、原速过渡 | 同参数渐隐；过渡放慢 1.2× |
| 切到“弹性”手感 | 该选项不存在 | 消息/开关/光晕统一变为 580ms、19.4% 过冲 |
| 关闭总开关 | — | 全部指标回退到宿主原生，设置入口保留以便再次开启 |

## 5. 性能与实现成本

- 渐隐是纯 `mask-image`，不参与布局；滚动测量为 1000ms 轮询 + 400ms DOM 防抖，不在每帧执行 JS。
- 光晕/扫光/推理环都是 CSS 动画，流式期间不增加逐帧 JS。
- 弹簧曲线是 CSS `linear()`，不需要 Framer Motion 或每帧 JS 弹簧求解。
- 音效只在发送/完成/出错三个状态变化时调度一次，单声 160–240ms，无音频文件加载。
- 新增体积：v0.4.0 构建约 51.7 KB（gzip 15.9 KB），其中四档弹簧曲线与音效调度占主要增量。

## 6. 主观评价与边界

**设计评估（非用户研究）**：

- 插件带来的提升是“细节层”的：第一眼不会改变布局，但连续使用后，滚动边界、数字跳动、状态等待和小按钮点击的粗糙感会明显减少。
- 最容易被感知的是**流式光晕/扫光**与**滚动羽化**；最容易被忽略的是**字重补偿**与**发丝描边**；音效属于强反馈，默认关闭是刻意选择。
- “弹性”档位（580ms、19.4% 过冲）风格化明显，适合演示或轻量场景；日常建议“从容”或“轻快”。
- 所有效果都保持 dsh 的色相、字体、布局与信息架构；插件不改变任何功能入口的位置。

**局限**：

- 未做正式可用性测试或问卷，主观结论仅基于计算样式、动画状态与设计目标。
- 暗色字重补偿只在可变字体生效；Windows 静态系统字体不会看到明显变化。
- 输入区命中区只覆盖 `[data-composer-seat]` 内的按钮，弹层/菜单内控件未覆盖。
- 横向渐隐与骨架扫光经调研暂缓：当前视图没有非代码/表格的横向滚动容器；骨架只有 CSS Module 哈希类名，缺少稳定标记。
- 0.4.0 截图已补齐 6 张：`v040-conversation-light/dark.png`、`v040-settings-section-light/dark.png`、`v040-settings-spring-light.png`、`v040-context-panel-dark.png`。其中弹簧截图展示「弹性」+ 音效开启的可选状态；默认仍是「从容」+ 音效关闭。

## 7. 复现方式

```bash
cd .testenv
DSH_HOME="$PWD/dsh-home" npx dsh web --port 3311 --no-open
# token 在 .testenv/web.log 第一行
```

在「设置 → 界面打磨」中：
1. 关闭/开启总开关，观察 `data-polish-*`、mask、令牌与正文计算值；
2. 切换四档弹簧，观察开关 `::after` 的 duration/timing-function；
3. 开启「轻量交互音效」后发送一条消息，观察发送/完成两声与 `AudioContext` 状态；
4. 在输入区添加按钮上方 4px 处点击，对比「输入区命中区」开关。

## 8. 建议

- 日常使用：保持默认「从容」，按需开启音效；如果更在意即时反馈，选「轻快」。
- 低性能/远程桌面：可关闭「排版光学微调」与「会话状态光晕」，保留渐隐与阴影。
- 第三方插件较多时：保留「插件界面适配」，遇到兼容问题单独关闭该组即可。
- 后续：在出现稳定横向滚动面板/骨架标记后，再评估横向渐隐与骨架扫光。
