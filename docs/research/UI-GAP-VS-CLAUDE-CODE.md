# dsh vs Claude Code 桌面端：UI 体验差距评估

> 日期：2026-10-30
> dsh 基线：0.2.1-rc.5（53 个 `dsh-client-ui-*` 包 + 隔离环境实机）
> Claude 基线：[open-claude-ui](https://github.com/Caho1/open-claude-ui) 对 Claude Desktop 2.0 / 内置 Claude Code 的逆向研究（社区项目，非官方）
> 目的：回答「功能已不少，还差哪些**体验**」，并区分哪些差距能由 `dsh-ui-polish` 补、哪些必须动 dsh 核心或第三方插件。

## 0. 证据等级与边界

- **dsh 侧**：以实际安装包的 slot/快捷键/样式/字符串为证据（如「审批只有 allow-once/reject」「Chat 内无 Show more/消息编辑」「草稿持久化但入队消息不持久化」「无多窗口/pop-out」均为 bundle 级核实）。
- **Claude 侧**：open-claude-ui 是第三方逆向，**不是官方规格**。其中 `docs/v1/03–06` 与 `docs/v2/02–04` 的自洽度最高；「Vibrancy 玻璃」「Broker–Replica 多窗口」「Cowork 看板」属于推断或版本相关，本文按「有研究证据」而非「官方确认」对待。
- 本文只比较**体验形态**，不比较模型能力、价格或生态。

## 1. 结论摘要

dsh 的功能面已经非常完整，甚至在 Agent 可观测性、计划评审、右栏工作台、插件扩展上**领先** Claude Code 桌面端。真正的差距不在"有没有"，而在四个体验层：

1. **阅读与排版的光学质量**：暗色字重补偿、数字等宽、0.5px 发丝线、7 段非线性渐隐、长消息收束、流式逐字显影。
2. **动效的物理系统**：命名弹簧预设、双频推理光晕、共享元素转场、骨架/胶囊微动效；dsh 目前是"令牌级时长 + 少量关键帧"。
3. **高密度多任务工作台**：Claude 用 28px 会话行（分支/PR/心跳/权限模式）+ 弹出式多窗口；dsh 是单窗口 + 状态点，会话行信息密度和多会话并行明显更低。
4. **产物、媒体与可靠性语义**：Claude 有沙箱产物分屏、语音/朗读、离线零丢失队列、时限式 Always Allow；dsh 的对应能力分散在预览器、实验包和 Host 策略里，尚未形成同等体验。

一句话：**dsh 赢在"Agent 透明度与扩展性"，Claude 赢在"阅读手感、信息密度与多任务并行"。**

## 2. 差距清单（按体验维度）

优先级：**P0** 日常手感明显、插件可低成本补齐；**P1** 有感知、需要设计决策或中等改动；**P2** 结构性能力，需 core / 第三方插件。
归属：**插件** = dsh-ui-polish 可做；**核心** = dsh 包；**三方** = 生态插件（如 better-sidebar）。

## 3. dsh 已经领先、不要为"对齐 Claude"而回退的部分

1. **Trajectory 事件账本**：轮次时间线、TTFT/解码拆分、请求/工具/系统提示检查器、懒加载历史。
2. **Plan review 一等公民**：plan chip、计划卡、Approve/Refuse/Request changes、侧栏预览；Claude 研究里没有同等的计划审批面。
3. **Subagent 可观测性**：血缘面包屑、切换器、后代树、侧栏子会话、只读记录。
4. **右栏工作台**：双 pane、浮动、全屏、拖拽标签、按会话持久化；Claude 的分屏主要服务 artifacts。
5. **插件扩展面**：~70 个 slot、可替换 tab 类型/工具卡/设置页/文档预览器；Claude 桌面端无同等开放度。
6. **用量与上下文仪表**：轮次 token、缓存读写、会话统计、上下文环。
7. **中英双语、ARIA/焦点/快捷键体系、减少动效**。
8. **Queue + Steer 双模式**（Claude 研究只记录队列）。
9. **内置浏览器标签**（Claude 研究未记录）。
10. **插件/自动化/日程等全局面板**。

## 4. 对 dsh-ui-polish 的可落地差距（不改变 dsh 原生设计）

按"插件可做 + 观感收益 / 风险"排序：

### P0（v0.3.0 已完成大部分）

1. ✅ **7 段非线性渐隐 mask**：已换成 28px / 15-30-45-60-75-87-100% 的 7 档 alpha 曲线，仍作用于 scrollport，仍受 fades/plugins 门控；量化验证见 `docs/research/CDS-ASSET-MAP.md` §5。
2. ✅ **推理环境光晕**：未占用 `reasoning.body` 槽位（避免侵入 dsh 推理 DOM），改为给现有 `[data-step-process] [data-shimmer-decoration]` 推理分隔点加 1.8s accent 光环，并与 composer 光晕共用 `data-polish-glow-*` 状态机；遵守 reduced motion。
3. ✅ **数字等宽与发丝线**：时间/轮次/用量/composer 统计/代码已 `tabular-nums`；dsh 的 `--dsw-elevation-stroke` 本身就是 0.5px，本轮只调颜色到 10%/9%。
